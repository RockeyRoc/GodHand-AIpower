# GodHand AIpower 1.3.0 实现状态

记录日期：2026-10-20。本文记录 1.3.0 源码工作区与发布包的实际实现和验证状态。

## 已完成

### 传输与客户端接入

- 新增 stdio 传输：`GodHand.exe --mcp-stdio`（源码 `python main_work.py --mcp-stdio`）。stdio 进程是本机统一服务的客户端，已有 HTTP 服务时直接附着，没有时由该进程启动并持有服务；两条通道共用同一目标库、调度器和任务数据库。
- 统一工具 `godhand` 的 schema 由 `register_godhand()` 一次性注册，HTTP 与 stdio 共用同一份动作表和帮助文本，避免两条通道参数漂移。
- 本机控制通道补齐全套 action，GUI、HTTP MCP 与 stdio 桥调用同一实现。
- AI 中枢新增“写入 Codex 配置”：可选用户级 `%USERPROFILE%\.codex\config.toml` 或项目级 `<程序目录>\.codex\config.toml`。只替换 `mcp_servers.godhand` 表（含其子表），其余内容原样保留；写入前备份，写入后用 `tomllib` 解析校验，失败不落盘。
- 命令行等价入口：`GodHand.exe --install-codex-config user|project`。

### 目标授权

- 新增本机开关 `auto_authorize_imports`（默认 `false`）。开启后，新导入的目标立即加入允许列表；关闭时仍须按 ID 手动选择。
- 开关只能在本机 AI 中枢修改，MCP 不能修改；保存时二次确认。已存在的记录不会被追溯授权。
- 导入、更新、删除、迁移与备份逻辑保持不变，凭据仍为 DPAPI 加密存储。

### 版本与构建

- 版本号收敛到 `AI中枢/version.py`；MCP 健康信息、MCP 服务标识、GUI 横幅/帮助、EXE 资源信息、默认输出目录和发布清单全部读取该常量。
- `AI中枢/__init__.py` 的 `VERSION` 改为从同一常量导入。
- Windows 原子写入遇到杀毒/索引器短暂占用时，`os.replace` 做有限重试；若移动已完成但返回错误则视为成功。

### 桌面端稳定性补强

- PHP 工具页现在显式持有顶层窗口，复制 Payload 与批量任务的界面回调不再因缺少 `root` 失败。
- 关闭窗口或后台服务已经退出时，任务停止会清理本地挂起状态并给出可读提示，不再把连接拒绝异常抛入 Tk 回调或关闭日志。
- Windows Store/AppContainer 等允许写文件但禁止重命名的目录，在原子替换重试失败后使用带内存回滚的直接提交，首次启动和后续配置保存均可继续完成。

### 沿用的 1.2.0 能力

- GUI 与 MCP 共用当前比赛目录的统一加密机子库；旧记录首次读取时先备份再事务迁入，保留历史 ID、凭据与授权引用。
- `targets_update`、重复导入差异字段、跨进程配置锁、迁移恢复入口与 MCP 连接自检保持原实现。

## 未实现（有意保留）

- 木马植入组件的私有心跳状态机、隐蔽控制与加密命令通道本轮未改动。新增隐蔽保活、规避检测与命令加密会实质增强对远端主机的隐蔽控制与持久化能力，因此不在本次发布范围内。
- 原有 WAF、监控、运维页面与靶机模板保持 1.2.0 行为。

## 已知边界

- stdio 通道由客户端拉起；若由该进程启动服务，stdio 会话结束即结束服务。需要长期驻留时先单独启动 `--mcp`。
- “导入后自动授权”降低了导入到可执行之间的人工确认环节，只应在受控的赛前批量录入时开启。
- 未做真实靶场、真实客户端审批策略与跨平台远程验收；这些不因本地测试通过而被视为已验证。
