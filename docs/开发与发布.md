# GodHand 1.6 开发与发布

本目录维护本地 1.6.0；GitHub main 与 v1.5.0 保留稳定的 1.5。提交和推送前分别核对分支与版本。

## 修改入口

main_work.py 是 GUI 与原业务实现入口，main.py 为兼容入口。修改原业务后运行 AI中枢/generate.py，生成 business.py 与字段元数据。新增独立业务通过 OperationSpec 注册，GUI 与 MCP 共用任务服务。

| 组件 | 职责 |
| --- | --- |
| core、storage、target_store | 配置、加密机子库与任务记录 |
| service、worker、winjob | 调度、目标锁、超时、取消和进程清理 |
| server、stdio_bridge | HTTP、管理通道与 stdio 桥接 |
| endpoint | 正式固定端口及旧配置迁移 |
| clientconfig | Codex 配置渲染、备份和写入 |
| hub_gui、gui | AI 中枢配置页及主界面挂载 |
| defense_gui、防御模块 | AoiAWD 部署与防御适配 |
| release | 共用构建、模板处理和产物校验 |

GUI 在主线程读取表单快照，Worker 使用纯 Python 状态执行；结果通过分发器返回界面。网络和子进程设置超时；任务输出以 TaskResult、事件和产物表达。

## 版本与端口

版本只在 AI中枢/version.py 维护，GUI、健康查询、EXE 资源和发布清单读取同一常量。正式 GUI、HTTP、stdio 与配置导出统一为 127.0.0.1:18765；底层测试可使用随机端口隔离本机模拟服务。

旧自定义端口在服务停止后备份并迁移。发现旧端口仍运行时保留配置，提示先停止旧后台。不同比赛目录在固定端口上顺序切换。

stdio 在窗口版 EXE 中恢复客户端继承的标准管道。标准输出用于 MCP 协议，日志使用标准错误或本机日志；GUI 正常启动保持窗口模式。

## 检查与构建

使用 requirements.lock.txt 对应的 Windows Python 3.14 环境：

    python -B -m unittest AI中枢.test_resilience AI中枢.test_target_store AI中枢.test_targets AI中枢.test_acceptance AI中枢.test_transports AI中枢.test_defense AI中枢.test_aoi AI中枢.test_v16 -v
    python main_work.py --check-ui --data-dir ./GodHand-test-data/ui
    python main_work.py --doctor --data-dir ./GodHand-test-data/doctor
    python build_work.py --check

构建便携包，使用新的输出目录：

    python build_work.py --output ../GodHand-AIpower-便携版/GodHand-1.6.0_本次日期-dev --cache ../GodHand-tmp/build-1.6.0 --tools-root ./tools

核心构建使用 build_exe.py。首次构建前准备 tools/AoiAWD；aoi_bundle.py 根据固定来源与校验值生成 Windows 原生服务和 Linux 探针，来源与对应源码随工具配套保存。Tabby/WinSCP 的程序及许可证由 --tools-root 提供。

发布目录包含配套 EXE、_runtime、用户说明、docs、skill.md 和 skills/godhand。release-manifest.json 记录文件校验值；便携构建同时生成 ZIP 和 SHA-256 文件。

## 数据与文件边界

源码与发布清单排除个人连接配置、密钥、数据库、日志、缓存和测试目录。RSA 模板以占位符发布，使用 template_render 生成本机可部署产物。

docx/ 为本地 Word 目录，Git 与便携构建均排除；docs/ 正常随源码和便携包提供，其他位置的文件不因 .docx 扩展名被统一排除。保留第三方工具的资源、来源和许可证。

升级开发目录时，先保存旧 EXE/runtime，再安装同次构建的新 EXE/runtime；机子、配置和比赛数据继续保留。验收记录分别注明源码、本机模拟、冻结程序和实际客户端的结果。
