# 开发与发布

业务基线是本次导入的 YL。main_work.py 保留全部表单，main.py 只转发。备用入口独有的四组运维页面和 ToolsTab 已合并。未增加常驻 AI 侧栏。

工具管理模块/registry.py 定义 ToolSpec 和 Windows 参数构造。AI中枢/core.py 定义 OperationSpec、TaskContext、TaskResult、存储和 DPAPI。service.py 负责有界调度、目标修改锁、事件持久化、任务查询和收尾。winjob.py 将 Worker 及其子进程放入 Windows Job，限制取消范围。server.py 使用官方 MCP SDK 提供认证 HTTP 和本机控制接口。

gui_bridge.py 仅在 GUI 主线程获取表单快照。Worker 中使用 snapshot.py 的纯 Python 状态对象，不创建或读取 Tk。界面事件通过主线程定时回放。GUI 和 MCP 都调用 business.py 中提取的原 YL 实现。business.py 是生成文件：修改 main_work.py 的业务后运行 `python AI中枢/generate.py`，不可只改生成文件。闭包标识与原源代码位置绑定，应在构建前重新生成并测试。

本地范围配置不通过 MCP 开放修改。MCP 明确指定目标，服务端固定主机连接记录。修改任务按目标排序加锁，读取允许有界并发。服务停止先拒绝新任务，再结束所属任务进程树。Job 清理只能确认本机进程结束；远程命令是否已生效须通过状态查询核对。

不在模块导入阶段部署、联网或启动任务。网络和子进程必须有超时。新业务增加 OperationSpec 和独立参数，输出 TaskResult/产物；不要让外部 Agent 提交 Tk 对象或扩大范围。日志不写凭据，结构化结果与原始工具输出也需脱敏。比赛地址、密码、轮次不硬编码。

依赖见 requirements.lock.txt；当前源码随附 AI中枢/vendor 的 MCP 依赖供本机开发，基础 GUI/SSH 依赖由开发环境提供。安装/更新依赖安排在赛前。

```powershell
python -B -m AI中枢.test_acceptance
python main_work.py --check-ui --data-dir ./GodHand-test-data
python build_work.py --check
python build_exe.py --output 新的核心发布目录 --cache GodHand-tmp/build
python build_work.py --output 新的便携发布目录 --cache GodHand-tmp/build --tools-root YL_Phantom_Portable_Tools
```

两个构建脚本共用 release.py，使用目录式 GodHand.exe 和 _runtime。build_work 额外复制 Tabby/WinSCP 的程序文件，排除便携用户数据与 INI，并生成 ZIP。发布模板中的历史 RSA 密钥替换为占位符；使用 template_render 后才生成本机密钥及可部署产物。不要直接部署含占位符的 RSA 模板。

发布清单使用明确源文件列表，模块只包含代码/模板。verify 检查运行数据、历史私钥并生成 SHA-256 文件清单。需保留外部工具自带许可证及资源。YL 作者归属保留，后续公开发行前核对原项目和扩展许可证。

提交验收应区分：页面构建、原函数保留、模拟靶机验证、真实靶场验证、SDK 协议验证、实际客户端验证。覆盖表里的“接口登记”不等于全部远程场景已经通过。
