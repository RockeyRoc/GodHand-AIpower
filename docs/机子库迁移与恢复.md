# 机子库迁移、更新与恢复 · GodHand 1.6

## 升级时先做这三步

1. 停止旧版服务并关闭窗口，备份整个比赛数据目录。
2. 更新 EXE 与配套 _runtime，保留 管理工具/GodHand 中的机子、任务与凭据。
3. 启动新版，在“机子管理”核对记录；到 AI 中枢选择允许目标、保存并启动服务。

当前 Windows 用户可继续读取原有加密记录。不同比赛使用不同 --data-dir；固定端口同时运行一套后台，切换比赛前先停止原服务。

## 当前数据位置

GUI 与 MCP 共用当前比赛数据目录中 `tasks.sqlite3` 的 `targets` 表。机子记录整体使用当前 Windows 用户的 DPAPI 加密；来源、稳定 ID、版本号及连接索引用于管理查询。GUI 新增、编辑和删除不会再写旧 `machines.json`。

默认比赛目录为 `管理工具/GodHand`。通过 `--data-dir` 或 `GODHAND_DATA_DIR` 指定其他目录时，GUI 与无界面服务使用相同选择；命令行参数优先于环境变量。

## 首次升级

升级前退出旧版窗口和服务。首次读取机子或修改机子时，新版会处理当前数据目录里的旧 MCP 导入表，以及安装目录的 `管理工具/machines.json`：

1. 校验全部旧记录，保留原有目标 ID、凭据及其他历史元数据。凭据不同的相同连接保留为独立记录，并标记重复连接。
2. 在当前比赛目录的 `backups/targets-pre-unified-*.dpapi` 写入加密快照，并读取验证快照可解密。
3. 在同一数据库事务中迁入统一表并记录完成状态。数据损坏、磁盘写入失败或 ID 冲突时整次迁移回滚，原数据保留。

安装目录的 `管理工具/.godhand-targets-owner.json` 将旧机子文件绑定到首次迁移的比赛目录，其他比赛不会自动复制这批旧机子。迁移完成后，不再从旧文件重新导入；删除或编辑后的记录不会在重启时被旧文件恢复。

原 `machines.json` 和旧 MCP 表原样保留，供旧版回退使用；它们不再是新版的数据来源。旧文件仍可能含明文凭据，备份整套安装目录时应按私人数据保管。原文件被旧版再次修改后，新版不会自动同步这些改动，新增资料应从新版机子管理明确录入。

## 新增与显式更新

重复导入默认跳过。返回的 `differences` 只含字段名，`matching_ids` 列出已有连接 ID，不返回差异值，也不覆盖凭据。

编辑使用 `targets_update`，传入稳定 ID 和需要修改的字段；省略字段保持原样。建议携带 `targets` 返回的 `revision`，有其他客户端抢先更新时会返回版本冲突：

```json
{"action":"targets_update","arguments":{"id":"目标列表返回的 ID","changes":{"name":"新的资产名称"},"expected_revision":1}}
```

返回 `revision`、`changed_fields`、`requires_local_selection` 和 `allowed`。凭据值不会出现在更新响应中，也不能用 `[REDACTED]` 占位符覆盖原凭据。

地址、端口、路径等连接身份发生变化时，记录继续使用原 ID，但须在本机 AI 中枢按 ID 重新选择并保存。历史名称授权在连接身份变化后不再继续匹配新地址。“导入后自动授权新记录”默认关闭，关闭时导入不会授予执行权限；在本机明确开启后，仅新导入项会加入允许列表，能力开关仍生效。

删除只删除指定 ID。重新新增同一连接会得到新 ID，旧授权不会转移到新记录。同地址历史冲突中的其他记录保持原 ID。

## 从迁移备份恢复

迁移快照反映首次升级时的数据，不包含之后的编辑。它使用 Windows DPAPI，恢复时应使用原 Windows 用户环境；不要把它当成可跨机器直接解密的便携格式。

本地恢复入口 `Store.restore_target_backup(path)` 只接受没有任何机子或迁移状态的空目录，不覆盖现有机子。示例中的路径需要替换为本机路径，并在源码目录下运行：

```python
from AI中枢.core import Store

recovered = Store(root="D:/GodHand", data_dir="D:/GodHand-data/recovered-match")
result = recovered.restore_target_backup("D:/GodHand-data/current-match/backups/targets-pre-unified-示例.dpapi")
print(result)  # 只显示恢复数量、备份位置和是否需要本机选择
```

恢复保留稳定 ID 和凭据，所有恢复项都需要在本机重新选择允许目标。恢复后让 GUI 和 MCP 都使用新的比赛目录。需要回退旧版本时，原安装目录和原旧记录仍保留；不要让旧版与新版同时写同一个比赛目录。

日常完整备份应先停止使用该数据目录的服务，再备份整个比赛目录。请保留加密备份和原运行数据，发布包中不应包含这些文件。
