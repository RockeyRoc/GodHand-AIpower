# 防御中心操作说明 · GodHand 1.6

在“综合运维 → 防御中心”部署 AoiAWD 探针，并打开每台靶机自己的监测页。Core、Web 和 MongoDB 在本机 Windows x64 运行；Linux x86_64 靶机通过已有 SSH 连接回传。

## 部署与查看

1. 在机子管理保存目标的 SSH 资料，并在 AI 中枢选择允许目标。
2. 打开防御中心，选择目标并填写监测目录；需要 PHP Web 捕获时填写对应 Web 目录。
3. 检查环境，阅读目标架构、目录与 PHP 检查结果。
4. 部署后查看任务结果，再打开监测页，确认对应文件、进程或 Web 事件。
5. 结束使用时卸载恢复，查看恢复结果与保留的备份位置。

PHP Web 捕获按目标 PHP 环境部署；没有 PHP 的目标跳过该组件。可选 ELF 路径生成单独的 .guardianed 程序，保留原始文件；题目启动配置按实际需要另行切换。调整部署参数前先卸载恢复。

## AI 调用

全部能力通过 godhand 使用。先查询 capabilities 中具体 operation 的参数，再用 run 提交任务；task 与 logs 查看结果。

| 能力 | 目标 | 用途 |
| --- | --- | --- |
| defense_aoi_probe | 已允许的目标 ID | 检查 SSH、架构、目录和 PHP |
| defense_aoi_deploy | 已允许的目标 ID | 部署文件、进程及可选 PHP/PWN 探针 |
| defense_aoi_open | 已允许的目标 ID | 建立回传并返回本机监测 URL |
| defense_aoi_remove | 已允许的目标 ID | 停止探针并恢复 PHP 内容 |
| defense_aoi_start / status / stop | local | 管理本机监测服务；完整标识分别为 defense_aoi_start、defense_aoi_status、defense_aoi_stop |

watch_paths 为绝对目录列表；webdir、php_files 和 elf_path 根据具体目标填写。写入 PHP 前生成备份并检查语法。卸载会按部署记录恢复插入内容；并发编辑冲突时保留文件和备份，并返回冲突位置。

SSH 或本机监测服务中断期间暂停采集，PHP 保持业务响应。恢复连接后继续接收新事件，期间遗漏事件不补录。

## 其他防御能力

已有 Fail2Ban、Watchbird、Lynis、YARA 和 AIDE 适配继续通过 MCP 使用：

| 用途 | 查询方向 |
| --- | --- |
| 环境与工具状态 | defense_probe |
| Fail2Ban 状态、配置、封禁与恢复 | defense_fail2ban_* |
| Watchbird 状态、日志、配置与恢复 | defense_watchbird_* |
| PHP WAF 切换与恢复 | defense_waf_switch / defense_waf_rollback |
| 主机审计 | defense_lynis_audit |
| YARA 规则扫描 | defense_yara_scan |
| AIDE 初始化、检查与基线更新 | defense_aide_init / defense_aide_check / defense_aide_promote |
| 已有任务的证据流程与报告 | defense_workflow_run / defense_report |

先检查目标已安装工具，再按用户需要配置或运行。Fail2Ban 的 management_ip 填管理端到目标的来源 IP/CIDR；配置动作返回的备份路径可传入对应恢复动作。

专项 AI 操作见[技能流程](../skills/godhand/references/workflows.md)。上游与许可证见[来源](../防御模块/SOURCES.md)。
