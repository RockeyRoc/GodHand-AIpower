# 防御中心操作说明

防御中心位于“综合运维 → 防御中心”。GUI 和 MCP 共用 `AI中枢/operations.py` 中的 `OperationSpec` 与同一个任务服务。所有远程动作都使用已保存且已授权的目标记录；SSH 用户、端口和凭据从本机加密目标库读取。

首次接入建议选择 `defense_probe`。该检查只读取工具版本、Watchbird/PHP 文件状态和 Web 目录信息，不安装软件或改变配置。缺少组件会显示缺失原因。远程写操作需在本机“AI 中枢”授权目标后单独提交。MCP 可调用 `capabilities` 查看完整参数、默认值、副作用说明和选项。

## 能力列表

| 能力标识 | 作用 | 类型 |
|---|---|---|
| `defense_probe` | 探测 Fail2Ban、Lynis、YARA、AIDE、PHP 与 Watchbird 状态/版本 | 只读 |
| `defense_fail2ban_status` | 查询服务、Jail、当前封禁 IP 与版本 | 只读 |
| `defense_fail2ban_configure` | 启用或撤销独立的 `godhand-ssh` Jail；写入前备份、配置检查和重载 | 写入 |
| `defense_fail2ban_ban` / `defense_fail2ban_unban` | 对已存在 Jail 封禁或解封一个 IP | 写入 |
| `defense_fail2ban_rollback` | 恢复 `configure` 返回的备份路径 | 写入 |
| `defense_watchbird_status` | 检查 Watchbird 文件、序列化配置、PHP 语法和 `.user.ini` | 只读 |
| `defense_watchbird_logs` / `defense_watchbird_stats` | 读取指定日志末尾或统计最近最多 1000 行 | 只读 |
| `defense_watchbird_configure` / `defense_watchbird_rollback` | 备份后修改一个已知防护开关或恢复配置 | 写入 |
| `defense_waf_switch` / `defense_waf_rollback` | 检查 PHP 加载配置后切换/恢复 `.user.ini` | 写入 |
| `defense_lynis_audit` | 运行现有 Lynis 快速只读审计并解析告警/建议 | 只读 |
| `defense_yara_scan` | 用指定规则扫描指定绝对目录，输出命中规则和文件证据 | 只读 |
| `defense_aide_init` / `defense_aide_check` / `defense_aide_promote` | 显式初始化、检查和单独提交完整性基线 | 检查只读；初始化/提交写入 |
| `defense_workflow_run` | 执行下列证据收集流程，不自动处置 | 只读 |
| `defense_report` | 汇总已保存的防御任务，导出 JSON 与 Markdown | 本机只读 |

## MCP 示例

先调用 `godhand` 的 `action=capabilities` 查看参数，再使用 `action=run` 提交任务。`target` 必须为已保存的目标标识或 ID。

```json
{"action":"run","arguments":{"operation":"defense_probe","target":"目标ID","parameters":{"webdir":"/var/www/site with spaces"},"timeout":60}}
```

启用 Fail2Ban 策略时，`management_ip` 必须是 GodHand 管理端/运维出口到目标主机的来源 IP 或 CIDR，不能填写被管理主机本身的地址。配置操作会返回备份路径；保存后可将该路径传给 `defense_fail2ban_rollback`。策略默认关闭，程序不会在首次连接时启用封禁。

```json
{"action":"run","arguments":{"operation":"defense_fail2ban_configure","target":"目标ID","parameters":{"enabled":true,"management_ip":"203.0.113.8","maxretry":5,"findtime":600,"bantime":600}}}
```

YARA 和完整性检查示例：

```json
{"action":"run","arguments":{"operation":"defense_yara_scan","target":"目标ID","parameters":{"rules_path":"/opt/rules/site.yar","scan_path":"/var/www/site with spaces"},"timeout":240}}
```

```json
{"action":"run","arguments":{"operation":"defense_workflow_run","target":"目标ID","parameters":{"workflow":"integrity_review"},"timeout":300}}
```

Web 目录流程 `web_check` 需要 `rules_path`；主机巡检是 `host_audit`。流程中任一步失败都会保留已收集证据、写出报告，并将任务标记为部分失败。任务 ID 可继续通过 `task`、`logs`、`cancel` 查询或取消。报告可通过 `defense_report` 选取任务 ID，留空时汇总最近 100 个防御任务。

## Watchbird 与 WAF 切换

本适配器不安装 Watchbird。切换到 Watchbird 前会要求 Web 根目录存在 `watchbird.php`，目标存在 `/tmp/watchbird/watchbird.conf`，PHP CLI 可用且脚本 `php -l` 成功；配置文件必须能在禁用 PHP 类实例化的模式下读取并包含必要开关。GodHand WAF 切换会检查 `waf_strong.php`。`.user.ini` 只接受现有已知 WAF 指向，写入前备份，写入后回读验证；切换失败会尝试恢复原文件。`.user.ini` 的 PHP-FPM/Apache 运行时加载仍须通过授权 Web 检查确认。

日志可能包含请求头或请求内容。任务结果经过凭据脱敏；统计只输出最近样本的计数，不输出日志正文。流量重放和 Flag 替换不在该适配器内。

## 三类预设流程

- `host_audit`：组件探测、Fail2Ban 状态、Lynis 审计。
- `web_check`：组件探测、Watchbird 状态、YARA 目录扫描。
- `integrity_review`：组件探测、AIDE 完整性检查。

流程只收集证据；封禁、配置切换、初始化/提交基线都通过对应独立能力触发。
