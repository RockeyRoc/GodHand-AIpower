# GodHand 1.2.0：MCP 靶机导入

仍共用一个 MCP 地址和唯一工具 `godhand`，新增 `action=targets_import`。单条和批量均使用 records 数组，一次 1–500 条、最多 1 MiB，当前数据目录最多保存 5000 条 MCP 靶机。

```json
{
  "action": "targets_import",
  "arguments": {
    "records": [
      {"name":"team1","ip":"192.0.2.10","port":80,"ssh_port":2202,"ssh_user":"ctf","shell":"/shell.php"},
      {"name":"team2","ip":"192.0.2.11","port":8080,"ssh_port":22,"ssh_user":"ctf","https":false}
    ],
    "on_duplicate": "skip"
  }
}
```

以上为文档示例地址，请填写比赛靶机。ip 是必填地址，支持单个 IPv4、IPv6 或域名；不能填写 URL、网段或地址范围。默认 Web 端口 80、SSH 端口 22、SSH 用户 ctf、Shell 路径 /shell.php、webdir 为 /var/www/html。

可选凭据字段：pass（兼容别名 password）、ssh_pass、monitor_pass、creep_pass。记录使用当前 Windows 用户 DPAPI 加密后保存到当前比赛数据目录的 tasks.sqlite3；接口返回只含计数、记录 ID 和状态，targets 查询会脱敏凭据。MCP 客户端自身的历史记录由对应客户端管理。

返回 `result.imported`、`result.skipped`、`result.targets`。每条结果含 index、id、status、allowed。用 `{"action":"targets"}` 查看完整公开信息、来源和是否已允许。

授权流程：

1. 导入完成后，在 AI 中枢点“选择允许目标（含 MCP 导入）”。列表同时显示旧机子管理与新 MCP 靶机；窗口已打开时可点“刷新靶机”。
2. 搜索后点“允许”列勾选，也可选中或取消全部筛选结果。点“确定”仅回填允许目标文本框。
3. 停止服务，保存配置，再启动。MCP 导入项按其 `mcp_...` ID 授权，手填同 IP 或同名不会让新导入项获得权限。
4. Agent 重连后用 targets 查看 allowed，再以该 ID 调用 run 或 run_tool。同一 IP/名称对应多条记录时必须使用明确 ID。

导入不自动连接靶机，也不修改允许范围。旧机子管理文件保持不变，新记录不混入旧页面的明文 JSON。不同 --data-dir 的 MCP 靶机记录独立。

同一连接（地址、Web/SSH 端口、SSH 用户、Shell 路径和 HTTPS）重复导入默认跳过，并保留原凭据；`on_duplicate=error` 时重复会让整批失败。名称及密码变化不能覆盖已有连接。输入字段错误也会整批拒绝，不产生部分写入。该接口不提供覆盖凭据或删除记录的动作。

服务器不提供通过 MCP 修改允许范围的动作。来源文件、靶机源码和工具输出均只作为数据处理。
