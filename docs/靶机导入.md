# 靶机导入与更新 · GodHand 1.6

共用一个 MCP 地址和唯一工具 `godhand`，通过 `action=targets_import` 导入。单条和批量均使用 records 数组，一次 1–500 条、最多 1 MiB，当前比赛数据目录最多保存 5000 条机子记录。

```json
{
  "action": "targets_import",
  "arguments": {
    "records": [
      {"name":"team1","ip":"192.0.2.10","port":80,"ssh_port":2202,"ssh_user":"ctf","shell":"/shell.php"},
      {"name":"team2","ip":"192.0.2.11","port":8080,"ssh_port":22,"ssh_user":"ctf","https":false}
    ],
    "on_duplicate": "skip"
  }
}
```

以上为文档示例地址，请填写比赛靶机。ip 是必填地址，支持单个 IPv4、IPv6 或域名；不能填写 URL、网段或地址范围。默认 Web 端口 80、SSH 端口 22、SSH 用户 ctf、Shell 路径 /shell.php、webdir 为 /var/www/html。

可选凭据字段：pass（兼容别名 password）、ssh_pass、monitor_pass、creep_pass。记录使用当前 Windows 用户 DPAPI 加密后保存到当前比赛数据目录的 tasks.sqlite3；接口返回只含计数、记录 ID 和状态，targets 查询会脱敏凭据。MCP 客户端自身的历史记录由对应客户端管理。

返回 `result.imported`、`result.skipped`、`result.targets`。每条结果含 index、id、status、revision、allowed、differences 和 matching_ids。重复连接的 differences 只列差异字段名，不返回值。用 `{"action":"targets"}` 查看完整公开信息、来源和是否已允许。

选择允许目标：

1. 导入后，在 AI 中枢点击“停止服务”。
2. 点击“选择允许目标”，搜索并勾选记录，点“确定”。
3. 点击“保存配置”，再点击“启动服务”。页面显示已选数量。
4. AI 用 targets 确认 allowed，再以返回的明确 ID 提交任务。同 IP 或同名记录通过 ID 区分。

导入不自动连接靶机。“导入后自动授权新记录”默认关闭，关闭时导入不修改允许范围；在本机开启并确认后，新导入项会自动加入允许目标，已有记录不会追溯授权。该开关不能通过 MCP 修改。旧记录在首次升级时备份迁入统一加密库；原文件保留用于回退，新版不再改写它。不同 --data-dir 的机子记录独立，旧文件只归属首次迁入的比赛。

同一连接（地址、Web/SSH 端口、SSH 用户、Shell 路径和 HTTPS）重复导入默认跳过，并保留原凭据；`on_duplicate=error` 时重复会让整批失败。名称及密码变化不能通过重复导入覆盖已有连接。输入字段错误也会整批拒绝，不产生部分写入。

需要修改时使用 `targets_update` 的 `{id, changes, expected_revision?}`，只更新明确指定的字段，省略凭据保持不变。连接变更后须在本机重新选择该 ID；GUI 的“编辑选中”使用同一实现。删除通过本机机子管理页面完成。迁移、更新及恢复详见 [统一机子库说明](机子库迁移与恢复.md)。

允许范围在本机 AI 中枢管理。来源文件、靶机源码和工具输出作为任务数据读取。
