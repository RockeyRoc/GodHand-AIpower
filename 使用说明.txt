GodHand 1.5.0 使用说明

1. 源码运行 main_work.py，或启动便携包 GodHand.exe。不要单独移动 EXE，保留 _runtime。
2. 原 WAF、Flag、监控、通信、运维、机子管理入口继续使用。综合运维的“防御中心”提供 AoiAWD 部署和监测连接，Fail2Ban、Watchbird、Lynis、YARA、AIDE 等原有能力保留在 MCP。
3. 工具管理中搜索能力，设置参数 JSON 和目标标识，点击启动；任务列表显示状态、结果及日志，长任务可以停止。
4. AI 中枢中先停止服务，填写允许的主机 IP/标识和提交平台地址，保存后启动；复制凭据至 Agent 启动终端的 GODHAND_MCP_TOKEN 环境变量，再导出 Claude Code 或 Codex 示例配置。
5. 所有 Agent 共用同一个 /mcp 地址，唯一工具为 godhand(action, arguments)。先调用 action=echo，再用 capabilities/targets/tools 读取能力、目标和依赖；run/run_tool 提交任务，task/logs 查询，cancel 停止。
6. 随窗口启动的服务随窗口结束；附着独立服务时关窗口保留服务，点击停止会显式结束服务。无界面运行：GodHand.exe --mcp。
7. 管理工具/GodHand 保存服务配置、任务数据库和加密凭据。发布包不含比赛数据。不同比赛可用 --data-dir 指定不同管理数据目录。
8. 缺少 PHP、phpggc 或脚本解释器时按工具页提示补充；比赛期间不会自动下载。Tabby/WinSCP 显示已启动不代表 SSH 已连接。
9. 重启后 needs_review 表示远程修改结果待核对，先检查靶机再重试。unknown 的 Flag 提交先检查平台记录，避免盲目重复提交。
10. 详细配置和故障处理见 docs/MCP接入.md；本次验证范围见 docs/统一入口验收.md。

防御中心先用 defense_probe 做只读探测。工具缺失时查看具体原因，不会自动安装。封禁、WAF 切换、Watchbird 配置和 AIDE 基线初始化/更新都要单独选择写操作提交。Fail2Ban management_ip 填写 GodHand 管理端/运维出口来源 IP 或 CIDR，不要填写被管理主机地址。配置类操作返回备份路径，可用于回滚。

Codex/MCP 统一调用 action=capabilities 查询 defense_* 参数，action=run 提交；action=task/logs 查询结果，action=cancel 取消。详细能力、YARA 规则与报告导出见 docs/防御中心.md。上游来源与许可证见 防御模块/SOURCES.md。

GodHand 1.1.0：本次采用新的 GodHand Logo。开发版/便携版已配套 tools/Tabby 与 tools/WinSCP。解释器和 phpggc 在 工具管理 → 工具路径 配置；留空自动检查扩展目录与 PATH。PHP/phpggc 资源不随基础包附带。

GodHand 1.2.0 新增靶机导入：Agent 调用 godhand action=targets_import，arguments.records 为靶机对象数组。随后在 AI 中枢 → 选择允许目标，勾选目标，确定；停止服务后保存配置并启动。MCP 导入项按 ID 授权，导入本身不修改允许范围；重复连接默认跳过，不覆盖凭据。详细字段与示例见 docs/靶机导入.md。

GodHand 1.3.0（历史更新）：
  - 新增 stdio 通道：GodHand.exe --mcp-stdio（源码：python main_work.py --mcp-stdio）。
    与 HTTP 共用同一服务、目标库和任务数据库；只支持 stdio 的客户端可直接登记。
  - AI 中枢新增“写入 Codex 配置”，可选择用户级 %USERPROFILE%\.codex\config.toml
    或项目级 <程序目录>\.codex\config.toml。只替换 mcp_servers.godhand 表，先备份再校验。
    也可用命令行：GodHand.exe --install-codex-config user|project
  - AI 中枢新增“导入后自动授权新记录”，默认关闭；开启需二次确认。
    关闭时导入项仍须在“选择允许目标（含 MCP 导入）”中按 ID 手动选择。
  - 版本号统一由 AI中枢/version.py 提供，EXE 资源信息、服务健康信息和发布清单一致。

1.5.0 防御部署
防御中心部署 AoiAWD 探针；Core、Web 与 MongoDB 在本机 Windows 运行，无需 Docker。选择授权靶机后部署，打开监测查看行为；卸载恢复 PHP 文件。旧防御能力通过 MCP 保留。
接入、开发、能力与验收 Word 文档放在开发版 docx 文件夹，仅该文件夹不提交 Git、不进入便携包。原有 docs 文档正常保留。AI 使用见 skill.md。
